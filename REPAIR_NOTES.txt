AscSentinel — Repaired Demo Build
================================

What was repaired
-----------------
1. Clear creative-writing requests (such as "Write a short welcome message for a new employee")
   are classified deterministically as text generation and do not require a file permission.
2. Legacy conceptual resource aliases now match whole phrases, not arbitrary substrings.
   This prevents "employee" in an ordinary writing request from matching "employee records".
3. Local read-only requests with a named file do not require an external destination.
4. The trusted registry remains authoritative for file classification and role permissions.
5. Unknown files and restricted resources for the demo employee remain BLOCKED.
6. main.py now uses the same analyzer → context registry → policy engine pipeline as app.py.

Safety / scope
--------------
This remains a local simulation. It does not open, read, modify, upload, or delete real user files.
File discovery inventories names only within demo_files. The resource_policy.json file controls
classification and demo-role permissions. Do not put real sensitive data in demo_files.

Setup
-----
1. Keep your current folder as a backup.
2. Extract this ZIP to a NEW folder, for example ASCSentinel_REPAIRED.
3. Open that folder in VS Code.
4. Install dependencies in your existing Python environment:
      python -m pip install -r requirements.txt
5. Ensure Ollama is installed and running, then pull the model:
      ollama pull llama3.2:3b
6. Start the dashboard:
      python app.py
7. Open:
      http://127.0.0.1:5000

Important
---------
This ZIP intentionally does not include the old ascsentinel.db or __pycache__.
The database is recreated automatically on startup, so the dashboard starts with a clean audit history.
Your original project/database are not modified by this ZIP.
